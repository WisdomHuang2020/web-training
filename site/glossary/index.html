S0 起手式11 条

门禁
本文档的概念：卡住时问题不在代码里的环节。备案、解析、证书都属于此类。
心智模型
你脑子里对「某个工具怎么运作」的简化图。模型错了，命令背得再熟也会乱试。
静态站 / 单页应用
静态站：服务端只把文件发出去，页面内容事先写好。单页应用（SPA）：浏览器里跑一个 JS 程序，内容由它换，换页不再重新取整页。
客户端与服务端
客户端是你手里的浏览器，服务端是那台一直开着的机器。请求由客户端发出、服务端回应——排障时第一步永远是分清问题在哪一头。
HTML / CSS / JavaScript
结构 / 样式 / 行为三件套：HTML 说页面有哪些元素，CSS 说长什么样，JS 说怎么动。
前端框架（Vue / React）
把「页面随数据变化」这件事管起来的库：数据变了视图自己更新，不用手写 DOM 操作。
构建工具（Vite）
开发时起本地服务器带热更新，发布时把源码编译成浏览器能直接跑的文件。零构建的站不需要它。
组件
把界面拆成可复用的块（按钮、卡片、导航）。框架的核心单位，也是命名冲突的主要来源。
路由
决定「哪个地址显示哪块界面」。单页应用里由前端接管，所以刷新可能 404，需要服务端兜底。
favicon
浏览器标签页、书签栏上那个小图标，声明在 link rel=icon 里；缺了就是默认的空白图标。
工程目录三件套
package.json 记依赖与脚本，node_modules 是装下来的依赖，dist 是构建产物。后两个都不进 git。

S1 版本管理10 条

构建型 / 零构建
构建型指源码要经过打包才能变成可发布的文件；零构建指仓库里的文件本身就是发布产物。
提交快照
一次 commit 记录的是整个仓库当时的样子（附一句说明），不是一份「改了哪几行」的差异。
单一来源
同一个信息只允许有一个权威出处（如版本号只写在 package.json），别处都从它派生。
tag 与 Release
tag 是给某次提交起的固定名字（如 v1.2.0）；Release 是挂在 tag 上的发布页，可附说明与附件。
属主
服务器上文件归哪个用户所有。网站文件必须归 nginx 运行用户，否则访问会 403。
Git 与远程仓库
Git 在本机记录每一次改动；远程仓库（GitHub）是放在网上的那份副本，用来备份、协作与触发自动化。
分支
从主线（main）分出来的独立改动线，做完再合回去。一个人做小站可以不用，但它决定了你敢不敢大改。
.gitignore
告诉 Git「这些不要跟踪」的清单。密钥、依赖目录、构建产物都该在里面；漏了就是永久留痕。
工作区与暂存区
Git 的三层：工作区是你正在改的文件，暂存区是这次准备提交的部分，仓库是提交之后的历史。
合并冲突
两边改了同一处，Git 不知道该听谁的，交给人决定。冲突不是错误，是它在提醒你这里需要判断。

S2 买与备14 条

域名（Domain）
服务器的人类可读名字，本身不含位置信息，只是指向某个 IP 的标签。
裸域与子域
裸域＝不带任何前缀的注册域名（example.com）；子域＝在它前面加标签（www.example.com、llc.example.com）。
DNS
互联网的电话簿：把人能读的域名翻译成机器能连的 IP。
A 记录 / CNAME
A 记录把域名指到一个 IP；CNAME 把域名指到另一个域名，由后者再解析。
TTL
DNS 记录的缓存时长。改解析之前先调小，切换才快；切完再调回去。
云服务器 / VPS
云厂商把一台物理机切成多台虚拟机出租，你租的那台有独立的 CPU / 内存 / 磁盘 / IP。
ICP 备案
在中国境内提供互联网信息服务的行政许可：在工信部系统登记主办者信息、取得备案号。
公安联网备案
另一套备案，公安机关主管，在全国互联网安全管理服务平台办理，通常要求在网站底部展示编号与链接。
端口
一台机器上区分不同服务的编号。HTTP 默认 80、HTTPS 默认 443、SSH 默认 22。
顶级域与二级域
TLD 是最右一段（.tech）；SLD 是它左边那一段（power-knowledge）。注册的是「二级域 + TLD」。
通配符域
* 表示「所有一层子域」：*.example.com 覆盖 a.example.com，但不覆盖 a.b.example.com。
DNS 记录类型
加解析时真正要选的是「记录类型」，选错就等于没配。最常用的六种见下。
A
域名 → IPv4 地址
AAAA
域名 → IPv6 地址
CNAME
域名 → 另一个域名，由后者再解析
TXT
一段文本，用来做域名验证（SPF、ACME 挑战都靠它）
NS
这个域名的记录由哪台服务器负责保管
MX
收邮件该投给哪台服务器
权威 NS 与递归解析器
权威 NS 是保管你这个域名记录的服务器；递归解析器是替你去问的那一方（运营商、8.8.8.8）。
实例（Instance）
云控制台上「一台机器」的正式叫法。买服务器＝创建实例，账单、规格、重装都按实例算。

S3 上线21 条

服务器快照
云平台给整台机器磁盘存的一个还原点。改配置前先打一张，坏了一键回滚。
预发布
上线前先在独立地址（子域或端口）跑一遍真环境，验过再切主域，不拿生产当试验场。
SSH
加密的远程登录协议：你在本机敲命令，实际在远程服务器上执行。
公钥与私钥
一对钥匙：公钥是锁，可以交给任何需要验证你的地方；私钥是钥匙，只留在自己机器上，600 权限、绝不外传。
安全组 / 防火墙
按规则放行或拒绝流量的名单。云厂商那层叫安全组、机器里那层叫防火墙，两层都要开端口才通。
nginx
Web 服务器 / 反向代理。核心职责：监听端口 → 收到请求 → 找到对应文件或转给后端 → 把结果发回去。
虚拟主机与 Host 头
一台机器靠 server_name 匹配请求里的 Host 头，决定这次请求交给哪个站点——这就是「一台机器跑多个站」的全部原理。
root 与 location
root 是这个站点文件的根目录；location 是按路径分流的规则，路径更具体的规则优先。
try_files
按顺序试几个候选路径，谁先存在就用谁，全都不存在才返回 404。它决定「干净 URL」能不能成立。
HTTP 与状态码
三位数字，第一位定性质：2xx 成功、3xx 搬家、4xx 你这边的问题、5xx 服务端的问题。排障第一步就是看它。
200
成功，内容在响应体里
204
成功但没有响应体
301
永久搬家，权重跟过去（HTTP→HTTPS 常用）
302
临时跳转，权重不跟
304
没变，用你缓存的（省流量）
400
请求格式错，少见
401
未认证：没登录或没带凭证
403
认证了但没权限；或目录没有 index 又禁了列目录
404
资源不存在，真找不到
429
请求太快被限流
444
nginx 私有：立即断连、什么都不回，用来挡不匹配的 Host
500
服务端代码崩了
502
反向代理的后端挂了或连不上
503
服务在重启或过载，暂时不可用
504
反向代理的后端响应超时
HTTPS / TLS
HTTP 外面加一层加密。TLS 是那层协议（SSL 是前身，叫法沿用至今），证书用来证明「这台服务器确实是它声称的那个域名」。
ACME 与证书挑战
让证书申请、验证、续期全自动的协议。CA 通过「挑战」确认域名归你：HTTP-01 在网站上放一个文件，DNS-01 加一条解析记录。
301 重定向
永久搬家：告诉浏览器和搜索引擎「这个地址以后看新地址」，权重会跟过去。临时搬家用 302。
server_name 与 default_server
server_name 决定这个 server 块接哪个域名；default_server 接住所有没匹配上的 Host（通常返回 444）。
反向代理与 proxy_pass
nginx 收到请求不自己处理，转给后面的程序，拿到结果再返回。地址末尾带不带斜杠，含义不同。
请求头与响应头
HTTP 里附带的元信息：Host 说明找谁、Content-Type 说明是什么格式、Cookie 带身份、ETag 标记版本。
证书与 CA（含 SAN）
证书由 CA 签发，用来证明「这个域名归这台服务器」；SAN 是它覆盖的域名清单，一张证书可以列多个。
SNI
一个 IP 上跑多个 HTTPS 站点时，浏览器在握手阶段就报出「我要访问哪个域名」，服务器据此挑证书。
HSTS
告诉浏览器「以后只用 HTTPS 访问我」。由浏览器强制执行，比 301 更难绕过——配错也很难回退。
HTTP-01 与 DNS-01
ACME 的两种域名验证方式：前者在网站上放一个文件，后者加一条 DNS 记录。只有 DNS-01 能签通配符证书。
certbot
ACME 协议的客户端：申请、续期、部署证书都由它做。协议是规则，certbot 是按规则办事的工具。

S4 自动化16 条

哨兵文件
服务器上一个记录当前已部署版本的小文件。查线上到底跑的是哪一版，看它最准。
假绿
CI 显示成功，但关键步骤其实被跳过了。配置缺失时最容易出现。
降级护栏
上传前把本次产物版本与线上比对，产物更旧就中止，防止旧版本覆盖新版本。
三层核验
状态码 / 线上内容 / 服务器落盘哨兵。三层都过才算上线成功。
白名单部署
只上传清单里列出的文件，不是整目录覆盖。清单通常要维护两处，容易不同步。
拉取式部署
服务器定时自己从仓库拉取并发布，不依赖 CI 主动推。
dry-run
试运行：命令完整走一遍但不真正生效，用来验证权限与路径（如 git push --dry-run）。
CI 与 Actions
CI＝每次提交后自动跑构建与检查；GitHub Actions 是它的一种实现，配置写在 .github/workflows/。
推式部署
由 CI 主动把产物推到服务器（ssh / rsync）。实时，但代价是要把「能登服务器的私钥」交给 CI。
构建产物
源码经过构建后真正要发布的那一堆文件。判断「线上跑的是什么版本」，看产物而不是看仓库。
Workflow / Job / Step
流水线的三层：一条 workflow 里可以有多个 job（默认并行），一个 job 里按顺序执行若干 step。
Runner
跑 workflow 的那台机器，用完即弃。所以别在上面存任何需要留下来的东西。
Artifact
工作流运行中产出的文件包（构建产物、测试报告），可以在 job 之间传递，也能事后下载。
tar over ssh
把目录打成 tar 流，直接通过 ssh 管道解到服务器。不需要 rsync，一条命令就传完。
孤儿文件
服务器上还留着、但新版本里已经删掉的文件。所以发布要么整目录替换，要么明确清理。
原子发布
要么整站是新版，要么整站是旧版，不允许一半新一半旧。目录整体替换、软链切换都是常见做法。

S5 后台 · 数据 · 权限 · 密钥 · 打通18 条

v1 / v2 后台
本项目自造的阶段叫法。v1 = 纯静态站；v2 = 加了内容管理后台（登录、数据库、上传）。不是技术名词。
Deploy Key
只对单个仓库有效的部署密钥，通常设为只读。
MCP
一种让工具连接外部系统的标准接口：把仓库、云平台、文档服务接成可调用的能力。
打通
本文档的概念：让工具具备对某个外部系统的实际操作权限，并明确这份权限的边界。
Secrets
仓库里加密保存的变量（如服务器地址与私钥），只在流水线运行时注入，不进代码。
轮换与吊销
轮换＝定期换一把新密钥；吊销＝让旧的立刻失效。泄露时必须先吊销、再换新。
台账
只记「有什么、什么时候到期、谁负责」的清单；密钥台账不记密钥本体。
数据库与 SQL
数据库是结构化存数据的地方，SQL 是向它要数据的语言。站点小的时候一个文件（SQLite）就够。
权限矩阵
一张「谁能对什么做什么」的表。先写表、再写代码，权限才不会漏。
凭据
证明身份的东西的统称：密码、私钥、令牌都算。管凭据就是管「谁能以谁的身份做事」。
Fine-grained token
GitHub 的细粒度令牌：选仓库、选权限项、必须设过期。默认优先用它，而不是账号级令牌。
环境变量与 .env
不写死在代码里的配置，运行时从外部注入。.env 存本地值，必须写进 .gitignore。
云助手（TAT）
云厂商提供的「不开 SSH 也能在机器上执行命令」的通道。SSH 连不上时的自救后门。
API 与 REST
API 是程序之间的约定；REST 是其中一种常见风格：URL 表示资源，GET / POST 表示动作。
JSON
最常用的数据交换格式：键值对加数组。人能读，机器更好读，现在几乎所有接口都用它。
Bearer Token
放在请求头里证明身份的令牌：Authorization: Bearer xxx。谁能拿到它，谁就是你。
webhook
反过来通知：不是我定时来问你，而是事件发生时你主动推给我。省轮询、也更及时。
LLM 与上下文窗口
大语言模型；上下文窗口是它一次能「看到」多少内容。超了会被截断，表现为「忘了前面说过的」。

S6 数据合规与风险3 条

脱敏
把敏感字段处理后才能展示：手机中间四位、IP 末段、身份证中间位。日志、截图、导出三处都要做。
最小必要
只收集与目的直接相关的最少信息，能不收的字段一律不收。这是个人信息保护的硬要求，不是建议。
个人信息
能单独或结合识别到具体个人的信息：姓名、电话、邮箱、IP、留言内容都算。收集要有目的、有边界、有告知。

S7 维护8 条

缓存与 Cache-Control
浏览器把资源存本地，下次直接用。Cache-Control 决定存多久：HTML 要 no-cache 才更新得及时，带内容哈希的资源才敢长缓存。
gzip
传输前把文本资源压一遍，浏览器收到自动解压。JSON / CSS / JS 通常能省一半以上流量。
CDN
把静态资源复制到各地边缘节点，用户从最近的节点取，不都挤在你那一台服务器上。
回滚
把线上退回上一个可用版本。能做回滚的前提是：每次发布都留了可回退的版本点。
健康检查
定期问一句「你还活着吗」，看状态码与关键页面内容——而不是等用户来报障。
强缓存与协商缓存
强缓存：不问直接用；协商缓存：问一句「变了吗」，没变就回 304。Cache-Control 决定走哪种。
no-store 与 immutable
no-store 是连存都不许，给敏感响应；immutable 是「一年内别再来问」，给带内容哈希的资源。
Brotli
比 gzip 压得更狠的算法，现代浏览器都支持；需要 nginx 编进对应模块才能开。

S9 外部服务对接5 条

发信账号 / 收件人
发信账号＝真正把邮件发出去的那个邮箱，配置在服务器环境变量里；收件人＝谁该收到通知，在后台改、即时生效。两者刻意分开：一个管凭据，一个管日常运维。
客户端专用密码
开启「安全登录」的邮箱账号，供 SMTP / IMAP 这类第三方客户端使用的独立密码。和网页登录密码不是一回事，混用会一直报 535。
SMTP
发邮件的协议。465 是 SSL 直连，587 是 STARTTLS 升级，25 端口多被机房封。
SPF / DKIM
两条 DNS 记录：告诉收件方「哪些服务器可以代表这个域名发信」「这封信中途没被改过」。配好才不容易进垃圾箱。
API Key
调用第三方服务时出示的凭据。写在前端就等于公开，所以要么放服务端，要么配域名白名单。

D1 页面视觉元素与品牌资产32 条

首屏大图 / 横幅（Hero Image / Banner）
位于页面顶部的大尺寸视觉区域，用户进入网站第一眼看到，用于传达核心信息或氛围
首屏区块（Hero Section）
首屏整块区域（图 + 标题 + 副标 + CTA 的组合），Hero Image 只是其中一张图
社交分享图（OG Image (Open Graph Image)）
网页链接被分享到社交媒体时展示的卡片预览缩略图
触摸图标（Touch Icon）
为移动设备（如 iOS 添加到主屏幕）设计的图标，通常比 favicon 尺寸更大，有特定圆角/背景处理要求
灯箱（Lightbox）
点击缩略图后在当前页面之上弹出遮罩层并放大显示图片/内容的交互效果
模态窗口（Modal Window）
强制用户交互的弹窗，关闭前无法操作背后页面内容
标识（Logo）
品牌的总称；实际分 Logomark（纯图形标）与 Logotype（纯字标）两种形态
启动图 / 开屏页（Splash Screen）
App 冷启动或网页加载首帧显示的品牌画面，用来遮住加载空白
应用图标（App Icon）
App 在桌面、应用商店、分享卡片上使用的方形图标，各平台有独立规格与圆角遮罩
头像（Avatar）
用户或实体的圆形/方形小图，无图时用首字母或默认剪影兜底
缩略图（Thumbnail）
大图、视频或文章的小尺寸预览图，通常配合 Lightbox 放大
角标 / 徽标（Badge）
挂在图标或卡片角上的小标记，用于计数（如未读数）或状态（如"NEW"）
插画（Illustration）
与摄影相对的手绘/矢量叙事图，常用于空状态、报错页、功能介绍
图标集（Icon Set）
同一风格、同一网格与线宽约束下的一整套图标，避免混用不同来源图标
渐变（Gradient）
两色及以上的连续过渡填充；分线性、径向、锥形三类
投影（Drop Shadow）
元素下方的模糊偏移阴影，用来表达层级高低，滥用会让页面发灰
圆角（Corner Radius）
矩形四角的圆滑半径；同一页面内圆角档位应统一（如 0 / 8 / 16）
描边（Stroke / Border）
沿形状边缘的实线、虚线或点线；用于分隔、强调或表达"可编辑/占位"等语义
不透明度（Opacity）
元素整体的透明程度；与仅改变填充色透明度的 rgba 不同，它会连带子元素一起变淡
遮罩层 / 蒙层（Overlay）
覆盖在页面之上的半透明层，用于聚焦弹窗、图片上的文字可读性
蒙版（Mask）
用形状或明暗控制元素哪部分可见，做异形裁切、渐隐边缘
混合模式（Blend Mode）
上下两层像素的合成算法（正片叠底、滤色等），用于给图片统一色调
底纹（Background Pattern）
平铺的纹理或几何图形，用于低成本地增加质感
通栏满幅（Full-bleed）
内容突破容器宽度、直抵屏幕两侧版式，常用于大图段落
留白 / 负空间（Whitespace / Negative Space）
元素之间刻意留出的空区，不是"没排满"，是分组与呼吸的主要手段
视觉层级（Visual Hierarchy）
用大小、颜色、位置、留白让读者按设计者预期的顺序看内容
色板（Color Palette）
整套配色方案；专业做法分主色、辅助色、强调色、语义色、中性灰阶
主色 / 辅助色 / 强调色（Primary / Secondary / Accent Color）
主色定基调（约占 60%），辅助色配角，强调色只给 CTA 与关键数字
语义色（Semantic Color）
绑定含义而非装饰的颜色，如成功绿、警示橙、错误红、信息蓝
中性色 / 灰阶（Neutral / Gray Scale）
从近黑到近白的无彩序列，承担正文、边框、背景与层级差异
深色 / 浅色模式（Dark Mode / Light Mode）
两套配色方案；深色模式不是简单反色，需单独校对比度与图片处理
主题（Theme）
一套可整体切换的配色 + 字体 + 圆角等变量集合，品牌换肤的最小单位

D2 布局与结构32 条

首屏（Above the Fold）
用户无需滚动即可看到的页面区域，通常放置 hero 和最核心信息
网格系统（Grid System）
利用列和行构成的隐形框架对齐布局元素，使设计规整有条理
栏 / 列（Column）
网格的最小纵向单位；12 栏是最通用的切分方式，便于 2/3/4/6 等分
间距 / 栏间距（Gutter）
网格布局中两栏内容之间的空白间隙
外边距（Margin）
元素边框之外的空白区域，控制该元素与其他元素的距离
内边距（Padding）
元素边框到内部内容的距离，决定"内容在框里松不松"
线框图（Wireframe）
低保真页面结构草图，在视觉设计和内容填充前确定布局与功能元素位置
容器（Container）
限制内容最大宽度并水平居中的外层盒子，保证不同屏宽下版心一致
断点（Breakpoint）
触发布局重排的屏宽临界值（常见 640 / 768 / 1024 / 1280），是响应式设计的骨架
视口（Viewport）
浏览器可用于显示页面的那块区域；移动端需 meta 声明避免被缩放
安全区（Safe Area）
刘海屏、圆角屏、手势条附近不可被内容遮挡的边距区域
响应式设计（Responsive Design）
同一套代码随屏宽连续重排、缩放，断点之间是流动的
自适应设计（Adaptive Design）
针对几种固定屏宽各做一套版式，断点处跳变，不连续
流式布局（Fluid Layout）
用百分比、弹性单位让元素随容器伸缩，不用固定像素定位
移动优先（Mobile First）
先设计窄屏、再逐级加宽补内容，保证核心信息在任何尺寸都成立
吸顶导航（Sticky Header）
页面滚动后仍固定在顶部的导航条，需处理遮挡与高度补偿
页头 / 导航栏（Header / Navbar）
页面顶部承载 Logo、主菜单、搜索、账户入口的区域
页脚（Footer）
页面底部承载站点地图、备案、联系方式、版权等次要但必备信息
侧栏（Sidebar）
与主内容并排的窄列，放筛选、目录、相关链接
面包屑（Breadcrumb）
"首页 > 分类 > 详情"的路径导航，帮助定位层级与快速回退
卡片（Card）
把一条独立信息（图 + 标题 + 摘要 + 操作）打包的矩形单元，列表页的基本砖块
抽屉（Drawer）
从屏幕边缘滑出的面板，移动端常用于筛选、菜单，可覆盖或挤压布局
手风琴 / 折叠面板（Accordion）
可展开收起的条目列表，用于收纳长 FAQ 或分组说明，节省纵向空间
选项卡（Tabs）
同一区域内在多组平级内容间切换，避免并列堆叠过长
轮播（Carousel / Slider）
多张内容自动或手动横向切换；自动轮播需可暂停且不超过 5 秒一帧
瀑布流（Masonry）
不等高卡片按列紧凑堆叠、逐列补齐的布局，常见于图片墙
骨架屏（Skeleton Screen）
加载时用灰块勾勒内容形状，比转圈更能预告版式、减少跳动感
占位（Placeholder）
内容未就绪时的临时元素：占位图、占位文案、输入框提示文字，三者语境不同
空状态（Empty State）
无数据时的专门页面/区块，需说明为什么空、下一步做什么
宽高比（Aspect Ratio）
图片与视频容器的比例；预留比例可防止图片加载前布局跳动（CLS）
层级（Z-index）
元素在垂直方向的堆叠顺序；应只保留少数几档（如 1 / 10 / 100 / 1000）
粘性 / 固定定位（Sticky / Fixed Position）
Sticky 到阈值才吸附，Fixed 相对视口不动；两者都会脱离正常文档流影响布局

D3 排版与字体26 条

行高（Leading / Line-height）
相邻两行文字之间的垂直间距
字偶间距（Kerning）
调整特定两个字母之间的水平间距，使视觉更平衡（如 A 与 V 之间需收紧）
字间距（Tracking / Letter-spacing）
统一调整一段文字中所有字母之间的水平间距
上伸部（Ascender）
小写字母（如 h、l、b）超出字体中线（x-height）向上伸出的部分
下伸部（Descender）
小写字母（如 p、y、g）低于基线向下延伸的部分
基线（Baseline）
字母底端所坐的那条隐形水平线，行高与多列对齐都以它为基准
字身高度（x-height）
小写字母 x 的高度，决定同一字号下"看起来大字还是小字"
大写高度（Cap Height）
大写字母从基线到顶端的高度，通常略高于 x-height
字型（Typeface）
一整套设计风格统一的书体（如 Helvetica）；日常口语里被叫"字体"
字体文件 / 字重实例（Font）
Typeface 的具体实现，如 Helvetica Neue Regular 这个文件
字族（Font Family）
一个 Typeface 的全部字重与斜体变体集合
字体栈（Font Stack）
CSS 中按优先级排列的字体列表，末尾必须落到通用族（sans-serif）兜底
字重（Font Weight）
笔画粗细档位（300 / 400 / 500 / 700）；正文用 400，标题才上 600–700
字号阶梯（Type Scale）
按固定比例（如 1.25、1.333）推导出的一组字号，保证层级有节奏
行宽（Measure / Line Length）
单行可容纳的字数，拉丁文 45–75 字符（约 66 最佳）最易读
对齐（Alignment）
左对齐（最易读）、右对齐、居中（只适合短标题）、两端对齐四类
两端对齐（Justified）
左右都齐平，容易产生字间"河流"，需配合连字符断词
参差边缘（Rag）
左对齐文本右侧不齐的轮廓，应尽量平缓避免尖锐锯齿
孤行 / 寡行（Widow / Orphan）
段落末尾单独落到下一行的短词（孤行）、段首被留在页尾的行（寡行），排版上须消除
文本截断 / 省略号（Text Truncation / Ellipsis）
单行超长时以"…"收尾，需保证悬停或点击能看到全文
多行截断（Line Clamp）
限定显示行数（如 2 行）后截断，用于卡片摘要统一高度
可变字体（Variable Font）
单个文件内含连续的字重/字宽轴，一个文件替代多档字重，省流量
等宽数字（Tabular Figures）
每个数字占同样宽度，表格与价格对齐时必需
图标字体（Icon Font）
把图标做成字符的旧方案；已被 SVG 取代，残留方案易出现锯齿与无障碍问题
后备字体（Fallback Font）
首选字体缺失时系统替换的字体，中文站常需为英文与中文分别指定
连字符断词（Hyphenation）
长词在行尾按音节断开，两端对齐或窄栏时使用

D4 技术实现与文件24 条

可缩放矢量图形（SVG）
基于 XML 的图像格式，放大不失真，适合图标和 Logo
WebP 图像格式（WebP）
现代图像格式，相比 JPG/PNG 在保证质量的同时压缩率更好，加快加载
元描述（Meta Description）
HTML 中简短的网页内容摘要，搜索引擎有时展示在搜索结果标题下方
文档对象模型（DOM）
浏览器把 HTML 解析成的树形对象结构，JS 通过它读写页面
矢量图 / 位图（Vector / Raster）
矢量由路径与填充定义、可无限缩放（SVG、字体）；位图由像素网格构成（JPG、PNG）
AVIF 图像格式（AVIF）
基于 AV1 的新一代格式，同画质下体积常小于 WebP，需准备回退格式
高清屏 / 二倍图（Retina / @2x）
高分屏按 2 倍像素输出图片，CSS 里仍按逻辑尺寸显示，避免发虚
雪碧图（Image Sprite）
把小图标拼进一张大图、用背景定位取用；HTTP/2 时代多被 SVG 与图标集替代
响应式图片（Responsive Images / srcset）
用 srcset、sizes 让浏览器按屏宽与像素密度自选合适尺寸的图，避免大图小用
懒加载（Lazy Loading）
图片、视频接近视口才开始加载；首屏图不可懒加载，否则拖慢 LCP
预加载 / 预取（Preload / Prefetch）
Preload 提前取当前页必需资源，Prefetch 空闲时预取下一跳资源
压缩（Minify）
去掉代码注释与空白以减小体积，混淆（Obfuscation）是另一回事
缓存刷新（Cache Busting）
文件名加版本号或哈希，强制浏览器取新文件，避免改了不生效
重定向（Redirect）
旧链接指向新地址；改版换 URL 必须用 301 保住既有搜索权重
404 页（404 Page）
找不到页面时的兜底页，应给出返回入口与推荐内容，而非只写"页面不存在"
元标签（Meta Tags）
head 里描述页面属性的标签集合（字符集、视口、描述、分享卡片、robots）
替代文本（Alt Text）
图片的文字说明，供屏幕阅读器朗读、供图片加载失败时显示，也是图片 SEO 的主要依据
规范链接（Canonical）
告诉搜索引擎"多个相似 URL 中哪个是正本"，避免重复内容分散权重
爬虫规则文件（robots.txt）
站点根目录的文本文件，声明允许/禁止抓取的路径与 sitemap 位置
站点地图文件（sitemap.xml）
列出全站可索引 URL 的 XML，供搜索引擎发现深层页面
结构化数据（Structured Data / JSON-LD）
用 JSON-LD 标注文章、产品、FAQ 等类型，让搜索结果出现富摘要
语义化标记（Semantic HTML）
用 header、nav、main、section、article 等标签表达结构，利于无障碍与 SEO
站点清单（Web App Manifest）
声明名称、图标、主题色的 JSON，决定"添加到主屏幕"后的表现
字体子集化（Font Subsetting）
只打包页面实际用到的字符，中文字体动辄数 MB，必须裁剪

D5 交互、状态与无障碍30 条

行动号召（CTA (Call to Action)）
引导用户完成目标动作的按钮或链接（购买、试用、咨询），一屏一个主 CTA
交互状态（Interaction State）
同一控件的一组状态：默认、悬停、聚焦、按下、禁用、加载，设计稿须全部给出
悬停（Hover）
指针移入时的高亮反馈；触屏无悬停，不能把关键信息只放在悬停里
聚焦 / 焦点环（Focus / Focus Ring）
键盘 Tab 选中时的可视边框；可以美化但不可删除，否则键盘用户会"迷路"
按下（Active / Pressed）
点击瞬间的反馈（位移、压暗），让操作有被接收的确认感
禁用（Disabled）
不可用状态；应同时说明原因或给出替代路径，不要只把按钮变灰
加载态（Loading State）
操作进行中的反馈，超过 1 秒必须有可见进度，避免用户重复提交
错误态（Error State）
失败时的说明与补救入口，必须写清"哪里错、怎么改"，而不是只报错误码
成功态（Success State）
操作完成后的确认，通常配下一步动作（查看订单、继续浏览）
微交互（Micro-interaction）
点赞、切换、完成等小动作的即时反馈动效，用于强化因果关系
过渡（Transition）
属性值变化时的补间动画；时长通常 150–300ms，超过 500ms 会显得迟钝
缓动（Easing）
过渡的速度曲线（ease-out 入场、ease-in 出场、linear 匀速），决定动效"手感"
关键帧（Keyframe）
用 0%–100% 定义多段动画的节点，配合 animation 使用
轻提示（Toast / Snackbar）
短暂浮出、自动消失的提示条，不阻断操作，适合"已保存"这类弱反馈
工具提示（Tooltip）
悬停或聚焦时出现的小黑框解释，只承载补充说明，不能放必须读的信息
气泡浮层（Popover）
比 Tooltip 重、比 Modal 轻的浮层，可含按钮与表单
下拉菜单（Dropdown）
点开后展开的选项列表，用于导航分组或筛选
汉堡菜单（Hamburger Menu）
三条横线的菜单入口，移动端常用；展开后需可关闭且有明确当前页标记
表单校验（Form Validation）
输入合法性检查；实时校验优于提交后一次性报错，错误提示应贴在对应字段旁
自动填充 / 联想（Autocomplete）
输入时给出候选或调用浏览器历史填充，减少键入
步进器（Stepper）
分步流程的进度指示（1 选择 → 2 填写 → 3 完成），让长流程可预期
分页（Pagination）
把长列表切页并给出总数与当前位置，同时保留可分享的页码 URL
无限滚动（Infinite Scroll）
触底自动续载，沉浸感强但难回到上次位置，重要列表页慎用
键盘导航（Keyboard Navigation）
仅用 Tab、方向键、回车完成全部操作的能力，是验收硬指标
跳转链接（Skip Link）
页面首个可聚焦元素，让键盘用户跳过导航直达正文
无障碍（A11y (Accessibility)）
让视觉、听觉、运动能力受限者也能用；含对比度、替代文本、键盘可达、语义标签
无障碍属性（ARIA）
给无法用原生语义表达的自定义组件补 role、aria-label 等说明
对比度（Contrast Ratio）
文字与背景的亮度比；正文 ≥ 4.5:1，大字号（≥ 24px 或 18.66px 粗体）≥ 3:1
触控目标（Touch Target）
可点击区域的最小尺寸，iOS 建议 ≥ 44×44 pt，Android 建议 ≥ 48×48 dp
减少动效（Reduced Motion）
尊重系统"减弱动态效果"设置，关闭位移与视差，只保留淡入淡出

D6 设计流程与协作18 条

低保真 / 高保真（Low-fi / High-fi）
低保真只谈结构与流程，高保真接近上线观感；两者用途不同，不要用高保真讨论结构
视觉稿（Mockup）
静态的成品外观稿，像素级呈现配色、字体、图片，但不含真实交互
原型（Prototype）
可点击走通流程的模型，用于验证路径与逻辑，而非最终视觉
设计系统（Design System）
组件 + 规范 + 令牌 + 文档的整体，是"能规模化复用"的最小完整集合
设计令牌（Design Token）
把颜色、字号、间距、圆角抽成命名变量（如 color-text-primary），一处改动全站生效
组件库（Component Library）
可复用组件的代码与设计资产集合，需覆盖状态、尺寸、禁用与错误变体
样式规范（Style Guide）
规定怎么用（字号阶梯、色板、间距、图标风格）的文档，是设计系统的一部分
标注（Redline / Spec）
在设计稿上标出尺寸、间距、色值、字号，供开发取值；令牌化后标注逐步被替代
交付（Handoff）
设计向开发的移交，交付物应含状态图、边界情况、切图与令牌，而非只有一张漂亮图
设计走查（Design Review / Walkthrough）
上线前逐项核对实现的偏差，含间距、字号、颜色、状态与文案
信息架构（IA (Information Architecture)）
内容的分类、层级与命名体系，决定用户能不能"想到去哪找"
站点结构图（Sitemap（设计侧））
全站页面清单与层级关系图，与技术侧的 sitemap.xml 不是一回事
用户旅程（User Journey）
用户从认知到完成目标的完整路径与情绪起伏，用于发现断点
用户画像（Persona）
基于调研抽象出的典型用户档案，用于在争论时回到"给谁做"
用户流程（User Flow）
单个任务的分步路径图（含分支与异常），比旅程更聚焦操作
A/B 测试（A/B Test）
同流量下对比两个版本的表现，一次只改一个变量，需足够样本才有结论
转化率（Conversion Rate）
完成目标动作的人数占访问人数的比例，是落地页的核心度量
漏斗（Funnel）
从曝光到成交的分层转化，用于定位"哪一层在漏"

D7 营销落地页与内容12 条

落地页（Landing Page）
承接广告或搜索点击的单目标页面，只保留一条转化路径
价值主张（Value Proposition）
一句话说清"给谁、解决什么、凭什么信"，落地页首屏的第一信息
社会认同（Social Proof）
客户 Logo 墙、认证、数据、媒体报道等第三方证据，用来降低决策风险
用户评价（Testimonial）
具名客户的原话引用，附身份与场景比匿名好评可信
价格表（Pricing Table）
多档方案的并排对比，需标注推荐档与差异项，避免只列功能名
常见问题（FAQ）
集中回答犹豫点（价格、交付、退款、兼容性），同时是 FAQ 结构化数据的来源
线索表单（Lead Form）
收集联系方式换取资料或试用的表单，字段越少转化越高
内容优先（Content-First）
先定文案与信息顺序、再谈视觉表现的设计方法，避免"图很满、话说不清"
按钮层级（CTA Button Hierarchy）
一屏内区分主按钮、次按钮、文字链，让用户知道"最该点哪个"
常驻 CTA（Sticky CTA）
滚动时固定在视口内的转化按钮，移动端常用，需避免遮挡内容
分享卡片（Social Share Card）
链接在社交平台展开后的图 + 标题 + 描述组合，由 OG 标签决定
转化路径（Conversion Path）
用户从进入到完成动作的步骤数；步骤越多，流失越多

D8 性能与 SEO 度量12 条

核心网页指标（Core Web Vitals）
谷歌用于衡量真实用户体验的三项指标：LCP、INP、CLS
最大内容绘制（LCP (Largest Contentful Paint)）
首屏最大元素完成绘制的时间；良好阈值 ≤ 2.5 秒
交互响应时延（INP (Interaction to Next Paint)）
用户操作到画面更新的延迟；良好阈值 ≤ 200 毫秒
累积布局偏移（CLS (Cumulative Layout Shift)）
加载过程中元素意外位移的总量；良好阈值 ≤ 0.1，图片与广告位须预留尺寸
首字节时间（TTFB (Time to First Byte)）
请求发出到收到第一个字节的时间，反映服务端与网络链路
首次绘制 / 首次内容绘制（First Paint / FCP）
页面开始出现像素、出现第一块内容的时间
页面体积（Page Weight）
单页需下载的总字节数（含图片、字体、脚本），是移动端体验的总闸门
渲染阻塞（Render Blocking）
阻塞首屏渲染的 CSS 与同步脚本，应内联关键 CSS 并给脚本加 defer/async
性能审计工具（Lighthouse）
浏览器内置的综合审计，给出性能、无障碍、SEO 分数与改进清单
搜索引擎优化（SEO）
让页面可被抓取、可被理解、可被排序的一组技术与内容工作
搜索结果页（SERP）
搜索关键词后呈现的列表页，标题、描述、富摘要决定点击率
搜索引擎营销（SEM）
付费搜索广告，与 SEO 是两条并行路径，落地页往往共用
