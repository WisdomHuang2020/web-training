术语表

共 106 条，9 组，按课程阶段排。通用术语取自建站全流程，本站自造的词（门禁、打通、假绿、哨兵…）也在里面 —— 这是第 11 条红线：自造的词必须在使用处给定义，否则就是给别人留债。

S0 起手式11 条

门禁
本文档的概念：卡住时问题不在代码里的环节。备案、解析、证书都属于此类。
心智模型
你脑子里对「某个工具怎么运作」的简化图。模型错了，命令背得再熟也会乱试。
静态站 / 单页应用
静态站：服务端只把文件发出去，页面内容事先写好。单页应用（SPA）：浏览器里跑一个 JS 程序，内容由它换，换页不再重新取整页。
客户端与服务端
客户端是你手里的浏览器，服务端是那台一直开着的机器。请求由客户端发出、服务端回应——排障时第一步永远是分清问题在哪一头。
HTML / CSS / JavaScript
结构 / 样式 / 行为三件套：HTML 说页面有哪些元素，CSS 说长什么样，JS 说怎么动。
前端框架（Vue / React）
把「页面随数据变化」这件事管起来的库：数据变了视图自己更新，不用手写 DOM 操作。
构建工具（Vite）
开发时起本地服务器带热更新，发布时把源码编译成浏览器能直接跑的文件。零构建的站不需要它。
组件
把界面拆成可复用的块（按钮、卡片、导航）。框架的核心单位，也是命名冲突的主要来源。
路由
决定「哪个地址显示哪块界面」。单页应用里由前端接管，所以刷新可能 404，需要服务端兜底。
favicon
浏览器标签页、书签栏上那个小图标，声明在 link rel=icon 里；缺了就是默认的空白图标。
工程目录三件套
package.json 记依赖与脚本，node_modules 是装下来的依赖，dist 是构建产物。后两个都不进 git。

S1 版本管理10 条

构建型 / 零构建
构建型指源码要经过打包才能变成可发布的文件；零构建指仓库里的文件本身就是发布产物。
提交快照
一次 commit 记录的是整个仓库当时的样子（附一句说明），不是一份「改了哪几行」的差异。
单一来源
同一个信息只允许有一个权威出处（如版本号只写在 package.json），别处都从它派生。
tag 与 Release
tag 是给某次提交起的固定名字（如 v1.2.0）；Release 是挂在 tag 上的发布页，可附说明与附件。
属主
服务器上文件归哪个用户所有。网站文件必须归 nginx 运行用户，否则访问会 403。
Git 与远程仓库
Git 在本机记录每一次改动；远程仓库（GitHub）是放在网上的那份副本，用来备份、协作与触发自动化。
分支
从主线（main）分出来的独立改动线，做完再合回去。一个人做小站可以不用，但它决定了你敢不敢大改。
.gitignore
告诉 Git「这些不要跟踪」的清单。密钥、依赖目录、构建产物都该在里面；漏了就是永久留痕。
工作区与暂存区
Git 的三层：工作区是你正在改的文件，暂存区是这次准备提交的部分，仓库是提交之后的历史。
合并冲突
两边改了同一处，Git 不知道该听谁的，交给人决定。冲突不是错误，是它在提醒你这里需要判断。

S2 买与备14 条

域名（Domain）
服务器的人类可读名字，本身不含位置信息，只是指向某个 IP 的标签。
裸域与子域
裸域＝不带任何前缀的注册域名（example.com）；子域＝在它前面加标签（www.example.com、llc.example.com）。
DNS
互联网的电话簿：把人能读的域名翻译成机器能连的 IP。
A 记录 / CNAME
A 记录把域名指到一个 IP；CNAME 把域名指到另一个域名，由后者再解析。
TTL
DNS 记录的缓存时长。改解析之前先调小，切换才快；切完再调回去。
云服务器 / VPS
云厂商把一台物理机切成多台虚拟机出租，你租的那台有独立的 CPU / 内存 / 磁盘 / IP。
ICP 备案
在中国境内提供互联网信息服务的行政许可：在工信部系统登记主办者信息、取得备案号。
公安联网备案
另一套备案，公安机关主管，在全国互联网安全管理服务平台办理，通常要求在网站底部展示编号与链接。
端口
一台机器上区分不同服务的编号。HTTP 默认 80、HTTPS 默认 443、SSH 默认 22。
顶级域与二级域
TLD 是最右一段（.tech）；SLD 是它左边那一段（power-knowledge）。注册的是「二级域 + TLD」。
通配符域
* 表示「所有一层子域」：*.example.com 覆盖 a.example.com，但不覆盖 a.b.example.com。
DNS 记录类型
加解析时真正要选的是「记录类型」，选错就等于没配。最常用的六种见下。
A
域名 → IPv4 地址
AAAA
域名 → IPv6 地址
CNAME
域名 → 另一个域名，由后者再解析
TXT
一段文本，用来做域名验证（SPF、ACME 挑战都靠它）
NS
这个域名的记录由哪台服务器负责保管
MX
收邮件该投给哪台服务器
权威 NS 与递归解析器
权威 NS 是保管你这个域名记录的服务器；递归解析器是替你去问的那一方（运营商、8.8.8.8）。
实例（Instance）
云控制台上「一台机器」的正式叫法。买服务器＝创建实例，账单、规格、重装都按实例算。

S3 上线21 条

服务器快照
云平台给整台机器磁盘存的一个还原点。改配置前先打一张，坏了一键回滚。
预发布
上线前先在独立地址（子域或端口）跑一遍真环境，验过再切主域，不拿生产当试验场。
SSH
加密的远程登录协议：你在本机敲命令，实际在远程服务器上执行。
公钥与私钥
一对钥匙：公钥是锁，可以交给任何需要验证你的地方；私钥是钥匙，只留在自己机器上，600 权限、绝不外传。
安全组 / 防火墙
按规则放行或拒绝流量的名单。云厂商那层叫安全组、机器里那层叫防火墙，两层都要开端口才通。
nginx
Web 服务器 / 反向代理。核心职责：监听端口 → 收到请求 → 找到对应文件或转给后端 → 把结果发回去。
虚拟主机与 Host 头
一台机器靠 server_name 匹配请求里的 Host 头，决定这次请求交给哪个站点——这就是「一台机器跑多个站」的全部原理。
root 与 location
root 是这个站点文件的根目录；location 是按路径分流的规则，路径更具体的规则优先。
try_files
按顺序试几个候选路径，谁先存在就用谁，全都不存在才返回 404。它决定「干净 URL」能不能成立。
HTTP 与状态码
三位数字，第一位定性质：2xx 成功、3xx 搬家、4xx 你这边的问题、5xx 服务端的问题。排障第一步就是看它。
200
成功，内容在响应体里
204
成功但没有响应体
301
永久搬家，权重跟过去（HTTP→HTTPS 常用）
302
临时跳转，权重不跟
304
没变，用你缓存的（省流量）
400
请求格式错，少见
401
未认证：没登录或没带凭证
403
认证了但没权限；或目录没有 index 又禁了列目录
404
资源不存在，真找不到
429
请求太快被限流
444
nginx 私有：立即断连、什么都不回，用来挡不匹配的 Host
500
服务端代码崩了
502
反向代理的后端挂了或连不上
503
服务在重启或过载，暂时不可用
504
反向代理的后端响应超时
HTTPS / TLS
HTTP 外面加一层加密。TLS 是那层协议（SSL 是前身，叫法沿用至今），证书用来证明「这台服务器确实是它声称的那个域名」。
ACME 与证书挑战
让证书申请、验证、续期全自动的协议。CA 通过「挑战」确认域名归你：HTTP-01 在网站上放一个文件，DNS-01 加一条解析记录。
301 重定向
永久搬家：告诉浏览器和搜索引擎「这个地址以后看新地址」，权重会跟过去。临时搬家用 302。
server_name 与 default_server
server_name 决定这个 server 块接哪个域名；default_server 接住所有没匹配上的 Host（通常返回 444）。
反向代理与 proxy_pass
nginx 收到请求不自己处理，转给后面的程序，拿到结果再返回。地址末尾带不带斜杠，含义不同。
请求头与响应头
HTTP 里附带的元信息：Host 说明找谁、Content-Type 说明是什么格式、Cookie 带身份、ETag 标记版本。
证书与 CA（含 SAN）
证书由 CA 签发，用来证明「这个域名归这台服务器」；SAN 是它覆盖的域名清单，一张证书可以列多个。
SNI
一个 IP 上跑多个 HTTPS 站点时，浏览器在握手阶段就报出「我要访问哪个域名」，服务器据此挑证书。
HSTS
告诉浏览器「以后只用 HTTPS 访问我」。由浏览器强制执行，比 301 更难绕过——配错也很难回退。
HTTP-01 与 DNS-01
ACME 的两种域名验证方式：前者在网站上放一个文件，后者加一条 DNS 记录。只有 DNS-01 能签通配符证书。
certbot
ACME 协议的客户端：申请、续期、部署证书都由它做。协议是规则，certbot 是按规则办事的工具。

S4 自动化16 条

哨兵文件
服务器上一个记录当前已部署版本的小文件。查线上到底跑的是哪一版，看它最准。
假绿
CI 显示成功，但关键步骤其实被跳过了。配置缺失时最容易出现。
降级护栏
上传前把本次产物版本与线上比对，产物更旧就中止，防止旧版本覆盖新版本。
三层核验
状态码 / 线上内容 / 服务器落盘哨兵。三层都过才算上线成功。
白名单部署
只上传清单里列出的文件，不是整目录覆盖。清单通常要维护两处，容易不同步。
拉取式部署
服务器定时自己从仓库拉取并发布，不依赖 CI 主动推。
dry-run
试运行：命令完整走一遍但不真正生效，用来验证权限与路径（如 git push --dry-run）。
CI 与 Actions
CI＝每次提交后自动跑构建与检查；GitHub Actions 是它的一种实现，配置写在 .github/workflows/。
推式部署
由 CI 主动把产物推到服务器（ssh / rsync）。实时，但代价是要把「能登服务器的私钥」交给 CI。
构建产物
源码经过构建后真正要发布的那一堆文件。判断「线上跑的是什么版本」，看产物而不是看仓库。
Workflow / Job / Step
流水线的三层：一条 workflow 里可以有多个 job（默认并行），一个 job 里按顺序执行若干 step。
Runner
跑 workflow 的那台机器，用完即弃。所以别在上面存任何需要留下来的东西。
Artifact
工作流运行中产出的文件包（构建产物、测试报告），可以在 job 之间传递，也能事后下载。
tar over ssh
把目录打成 tar 流，直接通过 ssh 管道解到服务器。不需要 rsync，一条命令就传完。
孤儿文件
服务器上还留着、但新版本里已经删掉的文件。所以发布要么整目录替换，要么明确清理。
原子发布
要么整站是新版，要么整站是旧版，不允许一半新一半旧。目录整体替换、软链切换都是常见做法。

S5 后台 · 数据 · 权限 · 密钥 · 打通18 条

v1 / v2 后台
本项目自造的阶段叫法。v1 = 纯静态站；v2 = 加了内容管理后台（登录、数据库、上传）。不是技术名词。
Deploy Key
只对单个仓库有效的部署密钥，通常设为只读。
MCP
一种让工具连接外部系统的标准接口：把仓库、云平台、文档服务接成可调用的能力。
打通
本文档的概念：让工具具备对某个外部系统的实际操作权限，并明确这份权限的边界。
Secrets
仓库里加密保存的变量（如服务器地址与私钥），只在流水线运行时注入，不进代码。
轮换与吊销
轮换＝定期换一把新密钥；吊销＝让旧的立刻失效。泄露时必须先吊销、再换新。
台账
只记「有什么、什么时候到期、谁负责」的清单；密钥台账不记密钥本体。
数据库与 SQL
数据库是结构化存数据的地方，SQL 是向它要数据的语言。站点小的时候一个文件（SQLite）就够。
权限矩阵
一张「谁能对什么做什么」的表。先写表、再写代码，权限才不会漏。
凭据
证明身份的东西的统称：密码、私钥、令牌都算。管凭据就是管「谁能以谁的身份做事」。
Fine-grained token
GitHub 的细粒度令牌：选仓库、选权限项、必须设过期。默认优先用它，而不是账号级令牌。
环境变量与 .env
不写死在代码里的配置，运行时从外部注入。.env 存本地值，必须写进 .gitignore。
云助手（TAT）
云厂商提供的「不开 SSH 也能在机器上执行命令」的通道。SSH 连不上时的自救后门。
API 与 REST
API 是程序之间的约定；REST 是其中一种常见风格：URL 表示资源，GET / POST 表示动作。
JSON
最常用的数据交换格式：键值对加数组。人能读，机器更好读，现在几乎所有接口都用它。
Bearer Token
放在请求头里证明身份的令牌：Authorization: Bearer xxx。谁能拿到它，谁就是你。
webhook
反过来通知：不是我定时来问你，而是事件发生时你主动推给我。省轮询、也更及时。
LLM 与上下文窗口
大语言模型；上下文窗口是它一次能「看到」多少内容。超了会被截断，表现为「忘了前面说过的」。

S6 数据合规与风险3 条

脱敏
把敏感字段处理后才能展示：手机中间四位、IP 末段、身份证中间位。日志、截图、导出三处都要做。
最小必要
只收集与目的直接相关的最少信息，能不收的字段一律不收。这是个人信息保护的硬要求，不是建议。
个人信息
能单独或结合识别到具体个人的信息：姓名、电话、邮箱、IP、留言内容都算。收集要有目的、有边界、有告知。

S7 维护8 条

缓存与 Cache-Control
浏览器把资源存本地，下次直接用。Cache-Control 决定存多久：HTML 要 no-cache 才更新得及时，带内容哈希的资源才敢长缓存。
gzip
传输前把文本资源压一遍，浏览器收到自动解压。JSON / CSS / JS 通常能省一半以上流量。
CDN
把静态资源复制到各地边缘节点，用户从最近的节点取，不都挤在你那一台服务器上。
回滚
把线上退回上一个可用版本。能做回滚的前提是：每次发布都留了可回退的版本点。
健康检查
定期问一句「你还活着吗」，看状态码与关键页面内容——而不是等用户来报障。
强缓存与协商缓存
强缓存：不问直接用；协商缓存：问一句「变了吗」，没变就回 304。Cache-Control 决定走哪种。
no-store 与 immutable
no-store 是连存都不许，给敏感响应；immutable 是「一年内别再来问」，给带内容哈希的资源。
Brotli
比 gzip 压得更狠的算法，现代浏览器都支持；需要 nginx 编进对应模块才能开。

S9 外部服务对接5 条

发信账号 / 收件人
发信账号＝真正把邮件发出去的那个邮箱，配置在服务器环境变量里；收件人＝谁该收到通知，在后台改、即时生效。两者刻意分开：一个管凭据，一个管日常运维。
客户端专用密码
开启「安全登录」的邮箱账号，供 SMTP / IMAP 这类第三方客户端使用的独立密码。和网页登录密码不是一回事，混用会一直报 535。
SMTP
发邮件的协议。465 是 SSL 直连，587 是 STARTTLS 升级，25 端口多被机房封。
SPF / DKIM
两条 DNS 记录：告诉收件方「哪些服务器可以代表这个域名发信」「这封信中途没被改过」。配好才不容易进垃圾箱。
API Key
调用第三方服务时出示的凭据。写在前端就等于公开，所以要么放服务端，要么配域名白名单。
