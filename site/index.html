01

这门课是什么 / 不是什么

边界先划清：它不追求讲全，只保证讲到的部分能照着做、做完了能自己验证。

是

  • 一条能照做跑通的完整链路：本地 → 仓库 → 服务器 → 域名 → 备案 → 上线 → 维护
  • 每个模块都有能力目标、产出物、验收判据、练习
  • 把踩过的坑当教材，每条坑都写清后果
  • 两条路线对照：构建型 / 零构建，失败模式正好相反

不是

  • 面面俱到的百科 —— 每个技术只讲到「够用且不出事」
  • 「点这里点那里」的截图流水账
  • 通用 AI 生成的模板教程
  • 只讲一种做法，换个项目就废
读者

能装软件、会看命令行输出即可；不要求会写代码

设备

按 Windows + Git Bash 讲，坑位也是这个环境的

账号

GitHub、云厂商、域名注册（建议域名与服务器同一家买）

预算

域名数十元/年 + 轻量云数十至百元/月 + 证书免费。价格随活动波动，以官网为准，本课不给具体金额

心理

备案是唯一无法用技术绕过的时间成本，必须提前排进计划

02

两条技术路线

本站所有模块都同时覆盖这两条路。为什么两条都讲：它们的失败模式完全相反 —— 只学一条，遇到另一类站就会用错排障方向。

构建型 · 单页应用

llc-design-tool
本机
需要构建（tsc + vite + 后处理）
上线
Actions 构建后 SSH 推送到服务器
延迟
约 4~5 分钟（含构建与传输）
失败主因
runner 到服务器链路不稳
适合
有交互、有计算、组件多

零构建 · 多页站

wx-seastar
本机
仓库根目录就是发布产物
上线
服务器定时自己拉取发布
延迟
≤2 分钟（巡检周期，不是端到端实测）
失败主因
白名单与实际文件不同步
适合
官网、介绍页、内容站

06

十一条通用红线

不分阶段，全程适用

这些不是「最佳实践」，是底线。违反其中任何一条，出了问题都不该算意外。

  1. 改前先读，改后回读。不接受「应该改好了」。
  2. 一次只改一件事，一次只提交一件事。
  3. 密钥永不进仓库，永不出现在截图里。
  4. 生产目录只允许部署脚本写，人上服务器只读优先。
  5. 没演练过的备份，不算备份。
  6. 发布必须给「已上线 / 未上线」的结论，不拿绿勾当证据。
  7. 多站共存时，只动自己的 web 根目录。
  8. 权限最小化：能只读就别给写。
  9. 不确定就停下问，不猜、不编、不用「通常」糊过去。
  10. 任何「顺手优化」都要先回答：不改会怎样。
  11. 自造的词必须在使用处给定义，否则就是给别人留债。
07

术语表

共 106 条

自造的词必须在使用处给定义 —— 这是第 11 条红线。这里集中放一份，讲义页会各自列出本讲用到的术语。

门禁
本文档的概念：卡住时问题不在代码里的环节。备案、解析、证书都属于此类。
心智模型
你脑子里对「某个工具怎么运作」的简化图。模型错了，命令背得再熟也会乱试。
静态站 / 单页应用
静态站：服务端只把文件发出去，页面内容事先写好。单页应用（SPA）：浏览器里跑一个 JS 程序，内容由它换，换页不再重新取整页。
客户端与服务端
客户端是你手里的浏览器，服务端是那台一直开着的机器。请求由客户端发出、服务端回应——排障时第一步永远是分清问题在哪一头。
HTML / CSS / JavaScript
结构 / 样式 / 行为三件套：HTML 说页面有哪些元素，CSS 说长什么样，JS 说怎么动。
前端框架（Vue / React）
把「页面随数据变化」这件事管起来的库：数据变了视图自己更新，不用手写 DOM 操作。
