01为什么重要

CI 的绿勾只说明「流水线跑完了」，不说明「文件到线上了」。配置缺失时 job 会显示成功但所有步骤 skipped，这就是假绿。

02要讲清的 3 件事核心要点

  • 每步回读 git 状态
  • 见到非自己的提交先停先报，不 revert 不 reset
  • 回滚走备份或快照；结论必须写「已上线 / 未上线」

03照着做：4 步操作顺序

  1. 发布后先看服务器上的版本哨兵
  2. 写下结论：已上线 / 未上线，并附证据
  3. 遇到非自己的提交先停先报，不 revert
  4. 回滚只走备份或快照

05练习15 分钟内可做完

06最容易踩的坑

把 CI 绿勾当证据——配置缺失时 job 会「假绿」：显示成功但所有步骤 skipped
后果：拿绿勾当上线证据，结果线上还是三天前的版本，而你以为已经修好了。

08本讲术语全部 28 条

  • 假绿：CI 显示成功，但关键步骤其实被跳过了。配置缺失时最容易出现。
  • 服务器快照：云平台给整台机器磁盘存的一个还原点。改配置前先打一张，坏了一键回滚。
  • CI 与 Actions：CI＝每次提交后自动跑构建与检查；GitHub Actions 是它的一种实现，配置写在 .github/workflows/。
