学完能照文档独立发布一次别人的站

01为什么重要

判断一次交接是否成功，标准只有一个：换个人只看文档、不看代码，能不能独立发一次版。做不到，说明文档写的是「我知道的东西」，不是「别人需要的东西」。

02要讲清的 3 件事核心要点

  • 构建型：CI 推送 + 版本哨兵 + 静态托管兜底
  • 零构建：拉取式 + 单源清单 + 内容后台
  • 四要素交接表：仓库 / 工作流 / 目标 / 验证

03照着做：4 步操作顺序

  1. 只读文档、不看代码
  2. 列出四要素：仓库、工作流、目标、验证
  3. 照文档独立发一次版
  4. 核对线上与仓库是否一致

08本讲术语全部 28 条

  • 构建型 / 零构建：构建型指源码要经过打包才能变成可发布的文件；零构建指仓库里的文件本身就是发布产物。
  • v1 / v2 后台：本项目自造的阶段叫法。v1 = 纯静态站；v2 = 加了内容管理后台（登录、数据库、上传）。不是技术名词。
  • 哨兵文件：服务器上一个记录当前已部署版本的小文件。查线上到底跑的是哪一版，看它最准。
  • 拉取式部署：服务器定时自己从仓库拉取并发布，不依赖 CI 主动推。
  • CI 与 Actions：CI＝每次提交后自动跑构建与检查；GitHub Actions 是它的一种实现，配置写在 .github/workflows/。
