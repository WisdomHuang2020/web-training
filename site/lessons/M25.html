M25访问监控与日志

所属路径 A / B / C 第 25 / 31 讲 S6 数据合规与风险
有人访问、有人攻击，你怎么知道
学完能能看到「谁来了、看了什么、出没出异常」，并知道这些记录本身也是个人信息

01为什么重要

没有监控的站，故障永远是用户先告诉你的。而日志里的 IP 属于个人信息——所以监控本身也是要合规处理的数据。

02要讲清的 4 件事核心要点

  • 三类监控：访问日志（nginx access.log）、可用性探活、业务统计（PV / UV / 来源）
  • 日志至少记：时间、来源 IP、UA、请求路径、状态码、耗时；保留期按需要定，常见 6 个月起
  • 告警要发到人能看到的地方：证书到期、磁盘满、5xx 突增、探活失败
  • 日志与统计都在处理个人信息（IP 属于个人信息），必须写进隐私政策

03照着做：4 步操作顺序

  1. 打开 access.log 确认字段齐全
  2. 配一条探活告警，发到人能看到的地方
  3. 制造一次 5xx，验证告警能到
  4. 把日志与统计写进隐私政策
tail -n 20 /var/log/nginx/access.log
curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" https://你的域名
# 告警口径：探活失败连续 3 次、或 5xx 占比突增

04产出物与验收做完怎么算过

产出物

一份监控清单 + 一条真能叫醒人的告警

验收判据

可验故意制造一次 5xx，10 分钟内收到告警
可验日志里能找到一条完整的请求记录（含状态码与耗时）

05练习15 分钟内可做完

给站点配一条探活告警，然后故意把 nginx 停掉，掐表看多久收到通知。

06最容易踩的坑

只装统计不看日志；日志开着但从不轮转，某天把磁盘撑满
后果：日志不轮转，某天把磁盘写满，nginx 直接 500——而且你还会以为是代码问题。
