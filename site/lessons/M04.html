M04Git 心智模型与提交纪律

所属路径 A / B / C 第 4 / 31 讲 S1 版本管理
提交是存档点，不是上传按钮
学完能把一次混杂的改动拆成干净的一到两个提交，并能解释「为什么提交完别人还看不见」

01为什么重要

把 Git 当网盘的人有三个典型症状：不敢改、一个提交塞十件事、以为 commit 完别人就能看见。三者来自同一个缺失：不知道中间还有「暂存区」这一层。

02要讲清的 4 件事核心要点

  • 心智模型＝你脑子里对「这工具怎么运作」的简化图；模型错了，命令背得再熟也会乱试
  • 四层搬运：工作区（改了）→ 暂存区（这次记哪几处）→ 本地仓库（快照）→ 远端（别人可见）
  • 一次 commit ＝ 给整个仓库拍一张带说明的快照，不是一份差异补丁；push 才同步到远端
  • 一次提交只做一件事；提交信息写「为什么」；分步 add → commit → push，禁用一条龙脚本

03照着做：4 步操作顺序

  1. 只改一处文案，不改别的
  2. git add 指定那一个文件，不用 git add .
  3. 提交信息写「为什么改」，不写「改了什么」
  4. git log --oneline 回读，确认历史可读
git add src/App.tsx
git commit -m "fix: 首页文案错字"
git log --oneline -5

04产出物与验收做完怎么算过

产出物

3~5 个语义化提交组成的干净历史

验收判据

可验git log --oneline 一眼看懂；git status 干净
人评能解释「commit 完为什么同事看不见」

05练习15 分钟内可做完

把一次「改文案 + 改样式」混在一起的改动，拆成两个独立提交。

06最容易踩的坑

一条龙脚本里的 push 触发环境重跑，产生重复提交、版本号空跳
后果：commit 之后以为发布完成，实际上 push 之前远端什么都没有，同事看到的一直是旧版本。

08本讲术语全部 28 条

  • 心智模型：你脑子里对「某个工具怎么运作」的简化图。模型错了，命令背得再熟也会乱试。
  • 提交快照：一次 commit 记录的是整个仓库当时的样子（附一句说明），不是一份「改了哪几行」的差异。
  • 服务器快照：云平台给整台机器磁盘存的一个还原点。改配置前先打一张，坏了一键回滚。
