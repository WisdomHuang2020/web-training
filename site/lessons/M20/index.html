M20后台形态选择

所属路径 C 第 20 / 32 讲 S5 后台 · 数据 · 权限 · 密钥 · 打通
静态站的边界在哪
学完能判断自己的需求该不该上后台，并画出数据流向

01为什么重要

静态站没有服务端，所谓「提交」其实写在访客自己的浏览器里，换台电脑就没了。这个边界必须先说清，否则你会以为自己在做后台。

02要讲清的 3 件事核心要点

  • 五种形态：纯静态 / 静态+本地存储 / 表单外挂 / 轻量后端+数据库 / 云托管
  • 判据：要不要多人同时写、要不要持久化、要不要登录、维护成本
  • 静态站的真实边界：数据只存在访客浏览器里

03照着做：4 步操作顺序

  1. 走一遍五问：多人写？持久化？登录？维护成本？预算？
  2. 画出一次提交的数据流向
  3. 定形态，写下不选其它四种的理由
  4. 确认数据存在哪台机器的哪个文件
判断口径（四问）：要不要多人同时写？要不要跨设备持久化？要不要登录？维护成本谁承担？
四问里有一个「要」，静态站就不够用了。

05练习15 分钟内可做完

拿自己的需求走一遍这五问，写下结论以及「不选其它四种的理由」。

06最容易踩的坑

用静态站假装有后台，换台电脑数据就没了
后果：用静态站做留言板，数据只在提交者本机，管理员永远收不到——上线一周才发现。

08本讲术语全部 68 条

  • 静态站 / 单页应用：静态站：服务端只把文件发出去，页面内容事先写好。单页应用（SPA）：浏览器里跑一个 JS 程序，内容由它换，换页不再重新取整页。
  • v1 / v2 后台：本项目自造的阶段叫法。v1 = 纯静态站；v2 = 加了内容管理后台（登录、数据库、上传）。不是技术名词。
  • 数据库与 SQL：数据库是结构化存数据的地方，SQL 是向它要数据的语言。站点小的时候一个文件（SQLite）就够。
